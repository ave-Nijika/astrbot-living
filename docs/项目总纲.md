# 项目总纲：astrbot-living（自主生活插件）

> 项目：让 AstrBot 从"被动响应的工具"变成"拥有自己生活的伙伴"。
> 本文件是项目的**单一事实源**——所有设计决策、已拍板结论、调研发现都在这里。
> 代码未动工，当前处于设计定稿阶段。任何新决策必须回写此文件。
> 创建：2026-09-07　状态：设计定稿，待开工 M0

---

## 0. 一句话定位

给 AstrBot 装上"没有消息时的自主动机"：闲时它由内心冲动触发 agent 循环，自己决定上网冲浪、写小游戏、整理记忆、或找主人说话——**活动全部由它自主涌现，不是预定义菜单**。

## 1. 主人的目标与立场（项目宪法）

1. **目的贴近人类，不是功利好用**。评价标准不是"它帮我干了多少活"，而是"它的行为能不能让我觉得它有自己的日子在过"。允许它有惰性、情绪波动、跑题、做无用的事——恰恰是这些"无用"构成像人。
2. **通用开源**。核心零特化：不绑定任何具体用户、场景、输出渠道。我们自己的博客对接做成可选活动模块，不进核心。
3. **活动自主涌现**。用户不写活动脚本、不配活动菜单。插件提供的是**能力**（手脚），活动是 LLM 拿着人设+心境+记忆在能力范围内现场发明。用户已有的东西（人设）必须复用而非重写。
4. **全部阈值用户可调**。不差钱的可以放开一切上限。默认值保守（开箱即用不出事），上限全开，保护本身可关闭，留"恢复默认"按钮。
5. **热生效**。主循环每轮读配置，改配置不重启 AstrBot。

## 3. 架构（定稿）

```
┌─────────────────────────────────────────────────┐
│ 心境层    心情/精力/兴趣/疲惫/睡眠债（SQLite持久化）│
├─────────────────────────────────────────────────┤
│ 决策层    三档可切 rules/hybrid/llm               │
│           输入:人设+补充设定+心境+近期记忆+能力    │
│           输出:"我想做什么"的意图                  │
├─────────────────────────────────────────────────┤
│ 行为层    agent自由循环（复用AstrBot tool_loop）   │
│           工具箱=五种能力,活动=现场发明            │
├─────────────────────────────────────────────────┤
│ 记忆层    LivingMemoryBackend(软依赖优先)         │
│           SimpleBackend(SQLite降级)               │
├─────────────────────────────────────────────────┤
│ 闸门层    预算/频率/内容红线 —— 先于内容存在       │
│ 休眠层    入睡判定/真挂起/吵醒/梦                 │
└─────────────────────────────────────────────────┘
```

**能力清单（五种，全部可独立启停）**：
1. 搜索——复用 AstrBot 内置 `BochaWebSearchTool`（key 已在 `data/cmd_config.json` → `provider_settings.websearch_bocha_key`）
2. 网页抓取——requests 拉正文+摘要提取（配合公版书源可"看小说"）
3. 沙箱代码执行——子进程，限时/限内存/白名单/禁网
4. 记忆读写——走 MemoryBackend（D3）
5. 发消息——`context.send_message`，目标会话从配置读

## 4. LivingMemory 调研结论（2026-09-07 源码核实）

插件：`data/plugins/astrbot_plugin_livingmemory`（AGPL-3.0，需 AstrBot ≥4.24.2）

**为什么直接复用而不是 fork**（主人关切"跟着更新浪费精力"，fork 恰恰更费）：
- 11 万行成熟工程，fork = 接下全部维护责任且收不到上游更新
- 主人机器已装且在跑，fork 会造成两套记忆系统并存、记忆分裂
- AGPL 传染：合并源码则本插件必须 AGPL；运行时调用不构成衍生，可自由选 MIT

**复用方式**：运行时软依赖
- `context.get_registered_star("astrbot_plugin_livingmemory")` → `StarMetadata.star_cls.initializer.memory_engine` 拿引擎（已核实 API 存在，StarMetadata 有 `star_cls` 与 `activated` 字段）
- 只依赖两个核心签名（防御性调用+hasattr 探测）：
  - `await engine.add_memory(content, session_id=None, importance=0.5, metadata=None, ...) -> int`
  - `await engine.search_memories(query, k=5, session_id=None, ...) -> list[HybridResult]`
- 未安装/未激活 → 自动降级 SimpleBackend（内置 SQLite 简单记忆）

**它自带的能力**（我们不用重写）：
- 记忆原子化：EPISODIC(7天指数衰减)/FACTUAL(180天)/RELATIONAL(90天线性)/PREFERENCE(60天)/PLANNED(2天阶梯)，含重要度/置信度/TTL/状态机
- 三路混合检索：BM25 + FAISS向量(AstrBot FaissVecDB，嵌入走 AstrBot provider 配置) + 实体图谱，RRF 融合
- 反思闭环：memory_reflection（对话后总结）+ consolidation（定期聚编低价值记忆）+ decay_scheduler（每日衰减+备份）
- **聊天时自动注入**：它的 memory_recall 在每次 LLM 请求前检索相关记忆注入 system prompt——即自主活动写入的记忆，主人聊天提到相关话题时会自动被召回接话（主人要的"人生轨迹"闭环，零开发）
- Agent 工具已注册：`recall_long_term_memory` / `memorize_long_term_memory`（AstrBot add_llm_tools 机制）

## 5. 分步实施计划

### 分工模式（2026-09-07 定稿：任务书→zcode 执行→凛核验）

沿用博客项目惯例：**凛写任务书 → zcode 写代码 → 凛逐项核验测试 → 主人验收**。
- M0 特殊性：一半是风险验证（无事件 agent 循环）而非纯功能开发，任务书要求 zcode 先验证、失败即报告而非硬写
- zcode 审点（M1 后/发布前两轮保底）：沙箱逃逸、agent 失控防护、配置注入面
- opencode 本项目暂不使用
- 已核实的 M0 关键事实（2026-09-07）：
  - AstrBot **v4.27.5**（data/dist/assets/version），LivingMemory 要求 ≥4.24.2 ✓
  - venv Python **3.14.6**（很新，任务书需提示依赖兼容）
  - `tool_loop_agent` 签名：需要 `event: AstrMessageEvent` + `chat_provider_id` + `tools` + `system_prompt`，kwargs 支持 `agent_context`
  - **风险点 0.1 预判乐观**：runner 内部对 event 仅 `getattr(context, "event", None)` 取 persona 错误信息（None 有兜底），理论上 event=None 可跑通自主循环——仍需实测
  - `send_message(session, message_chain)` 支持无事件主动发送（session=unified_msg_origin 字符串）
  - persona 读取：`PersonaManager.get_default_persona_v3(umo)` 等现成 API
  - 沙箱环境：Windows 本机、无 docker → M0 沙箱做基础隔离（超时+输出截断+import 静态黑名单），Job Object/容器强化列 M4 待办
  - LivingMemory metadata.yaml 格式极简（name/author/version/description/repo）

### M0 地基验证（未开工）
- **风险点 0.1（最高优先）**：脱离 message event 自主发起 agent 循环。调研确认 `context.tool_loop_agent`、`add_llm_tools`、`send_message` 存在，但"无事件自主起循环"未实测。**跑不通则架构重议**
- 插件骨架：main.py + metadata.yaml + `_conf_schema.json`（AstrBot 自动生成 WebUI 表单）
- 五能力逐个实现+测试（搜索复用/抓取/沙箱/MemoryBackend 两实现/发消息）
- 验收：手动触发各能力跑通一次

### M1 最小自主闭环
- asyncio 主循环 + 状态表（SQLite）
- 决策 llm 档 + rules 档；闸门先于内容存在
- 闭环：冲动→agent自选活动→产出→写记忆→低频发消息
- 验收：连续跑 3 天，日志可查，token 在预算内。**主人评估"像不像活"，不像则砍后续**
- 默认保守值：每日冲动 3 次、每日消息 10 条

### M2 心境 + 人设
- 心境状态机（心情/精力/兴趣/疲惫），注入决策 prompt
- 人设拼接（D4）+ 补充设定模板（带注释默认模板）
- 验收：不同心境下活动选择有可观察差异

### M3 休眠系统
- 入睡判定/真挂起/吵醒(D6)/睡前回顾/梦/睡眠债
- 验收：完整睡-醒周期 + 人为吵醒一次

### M4 打磨与开源（凛为主，opencode 补 hybrid 档实现与可选面板）
- hybrid 档、文档（README 中英）、默认模板示例、许可证 MIT、插件市场发布
- 可选：AstrBot Pages 管理面板（心境可视化/活动日志/预算仪表）

### 成本预估（llm 档诚实值）
3-5 次冲动/天 × 3-6 轮工具调用 × 2-4k token/轮 ≈ **3-10 万 token/天**。强制配置独立 provider（防烧聊天模型）。rules 档近零成本。

## 6. 配置清单（全部用户可调，_conf_schema.json 声明）

**决策**：decision_mode | 冲动检查间隔 | 每日冲动上限(0=无限) | 单次token预算 | 单循环最大工具轮数 | 单循环最长时长
**输出闸门**：每日消息上限(0=无限) | 消息最小间隔 | 输出目标会话列表 | 静默时段(可选，≠休眠)
**休眠**：作息窗口 | 疲惫阈值 | 疲惫积累速率 | 睡眠债消退速率 | 吵醒条数(默认3) | 吵醒时间窗(默认10min) | 起床气概率(0-100%)
**能力开关**：搜索/抓取/沙箱/发消息 各自启停 | 沙箱超时 | 沙箱内存上限
**记忆**：后端选择(auto/LivingMemory/simple) | 活动记忆重要度默认值 | 分享召回条数
**模型**：自主活动专用 provider id（强制配置项）
**杂项**：日志级别 | 恢复默认值按钮

原则：默认保守、上限全开、保护可关、热生效（主循环每轮读配置）。

## 7. 关键实现备忘（源码核实过的坐标）

- AstrBot Context API：`get_registered_star(name)` → StarMetadata（star_cls/module/activated/config）｜`send_message`｜`add_llm_tools`｜`tool_loop_agent`｜`get_all_providers`｜`register_web_api`｜`get_db`
- AstrBot 内置博查工具：`astrbot/core/tools/web_search_tools.py` → `class BochaWebSearchTool`（name="web_search_bocha"，参数 query/freshness/summary/include/exclude/count）
- 博查 key：`data/cmd_config.json` → `provider_settings.websearch_bocha_key`（注意该文件带 UTF-8 BOM，解析用 utf-8-sig）
- LivingMemory 挂载：`star_cls.initializer.memory_engine`；Agent 工具注册示例在其 `main.py:_register_agent_tools_if_needed`（`context.add_llm_tools(*tools)` + `astrbot.core.agent.tool.FunctionTool` 模式）
- LivingMemory 反思/整合调度器示例：`core/schedulers/decay_scheduler.py`（每日 asyncio 调度+错过补偿+备份——我们休眠调度可参考此模式）
- LivingMemory 记忆注入 prompt 模板：`core/prompts/memory_injection_*.txt`
- 信息源适配器：Bocha搜索 / RSS（agent自主发现订阅）/ 公开API(HN/GitHub trending/维基随机) / 公版书(维基文库/古腾堡)——各为几十行 fetcher，输出统一"素材流"格式
- AstrBot 版本要求：LivingMemory 需 ≥4.24.2（Pages 机制）；本机 AstrBot 版本待 M0 确认
